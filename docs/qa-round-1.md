## P2 — UX gaps from tester feedback

- [x] 8. After login the landing page flashes ~5s before redirecting. Add an auth-resolving state: minimal branded loading screen (logo + thin progress line) while session/role resolves, then route straight to the correct home. No landing flash. **Fixed** — root cause was the Google OAuth full-page redirect back to `/auth/callback`: on that fresh page load, `useStore`'s boot state had no tokens yet, so it defaulted to the unauthenticated view while the callback `fetch` (can take a few seconds against the Render free-tier backend) was in flight. Added `authResolving` screen (logo + thin animated progress line, `App.jsx`), and `useStore.js` now detects the OAuth callback at boot time and starts on that screen instead of "home". Regular email/password login was unaffected (stays on the Login screen with its own spinner, no page reload).
- [x] 9. Sessions expire after 12 hours of inactivity: frontend idle timeout (reset on interaction) + matching token lifetime on the backend. **Frontend fixed** — added `useIdleTimeout` hook (`src/hooks/useIdleTimeout.js`): tracks last-activity in localStorage, resets on mousemove/keydown/touchstart/scroll/mousedown, and logs out with a "session expired" toast after 12h. Boot-time check in `useStore.js` also clears a stale session on page reload after 12h idle (verified live by seeding a 13h-old timestamp and confirming reload wipes the session; a 5min-old timestamp survives reload). **Backend token lifetime is out of scope** — this repo is frontend-only, no Django backend present; the matching JWT/session lifetime change needs to happen in the `master-events-backend` repo. Also noticed while implementing: Google OAuth login (`App.jsx` `/auth/callback` handler) never calls `saveSession()`, so it doesn't persist `me_session` — Google-authenticated sessions may not survive a page reload today. That's a pre-existing bug outside this item's scope; flagging separately rather than bundling a fix in here.
- [x] 10. Resell/send: when a user holds N tickets for an event, let them choose how many (1..N) to list or transfer; price applies per ticket. **Frontend fixed** — added a quantity stepper (1..N, Phosphor Minus/Plus) to both `Resale` and `Transfer` screens in `TransactionScreens.jsx`, shown only when the ticket's `quantity` > 1. Resale price input is now labeled "per ticket" and the payout breakdown multiplies by quantity. Store (`useStore.js`) sends `quantity` in both the `resale/list/` and `transfer/` request bodies, defaults to 1 (not the full holding, to avoid accidentally listing/sending everything), and refetches `myTickets` from the server after success rather than guessing locally how a partial-quantity listing splits the record — the backend is the source of truth for that. Extracted the ticket-mapping logic (was duplicated) into a shared `setMyTicketsFromApi` store action used by both the initial fetch and these refetches. **Backend support unconfirmed** — verified the `quantity` field is sent, but I don't have access to the Django backend repo to confirm the `resale/list/` and `transfer/` endpoints actually honor it (extra JSON fields are typically ignored by DRF serializers, so today this may still resell/transfer the whole holding until the backend adds `quantity` handling). Live UI verification was inconclusive (a dynamic `import()` used to seed test state resolved to a separate module instance from the one the running app uses, so the stepper couldn't be visually confirmed against a real multi-ticket account) — code-reviewed and build-verified only, worth a manual pass once a real multi-ticket test account is available.
- [x] 11. `AttendeeWallet.jsx` — remove the redundant "My Wallet" title bar with back arrow; the wallet is a tab destination, the page heading is enough. **Fixed** — both the mobile `MobileTopHeader` and desktop `DesktopTopbar` in `App.jsx` already render "My Wallet" as the screen title via the shared `screenTitles` map (attendeeWallet is a `FULL_SCREENS` entry with its own title), so the component's own internal sticky header (back arrow + "My Wallet" text) was a true duplicate stacked underneath. Removed it along with the now-unused `ArrowLeft` import and `setScreen` var.
